# @mmmatvey122/k8s-logs-menu

Расширение для OpenLens: выгрузка логов всех подов микросервиса сразу — из нескольких кластеров и нескольких
сегментов за один заход. Вдобавок возвращает меню нод и подов (Logs, Shell, Attach), убранное из
OpenLens в версии 6.3.0.

## Установка

Скачать `.tgz` и перетащить его в окно OpenLens на страницу Extensions (или указать путь к файлу в поле и нажать
Install). Если стояла прежняя версия — сначала удалить её.

**После установки обязательно перезапустить OpenLens.** Расширение поднимает код в main-процессе, и без рестарта
обработчики не зарегистрируются.

Нужен `kubectl`. Он ищется в настройке Lens, в переменной `KUBECTL_PATH`, среди бинарников, скачанных самим Lens,
и в типовых местах установки. Если не нашёлся — страница попросит указать путь, и он запомнится.

## Где открыть

* в сайдбаре кластера — пункт **Service logs**;
* в палитре команд — `Service logs: скачать логи всего сервиса`.

## Как это работает

Страница ничего не знает о Kubernetes. Все запросы выполняет main-процесс расширения через `kubectl` с явным
kubeconfig и контекстом из каталога Lens:

```
kubectl --kubeconfig <путь> --context <контекст> ...
```

Поэтому работают exec- и OIDC-плагины авторизации, а кластер не обязан быть подключённым в Lens. Отсюда же
берётся многокластерность: main-процесс не привязан к фрейму открытого кластера.

## Мастер выгрузки

### 1. Clusters

Все кластеры каталога Lens, можно отметить сколько угодно. Рядом с именем - context из kubeconfig и метка
доступности: расширение само спрашивает у кластера `kubectl get --raw /version`. Проверка идёт при открытии страницы, по кнопке «Обновить» и по итогам выгрузки логов, параллельно, с таймаутом 5 секунд на запрос.

Метка показывает версию сервера зелёным, если всё в порядке, либо различает виды отказа: «нет доступа» -
проблема с учётными данными (истёкший токен, сертификат), «не отвечает» - сеть, VPN, таймаут, DNS.
Полный текст ошибки виден во всплывающей подсказке. Статус подключения, который показывает сам Lens, намеренно не
используется: он говорит лишь о том, открыт ли кластер в Lens, и ничего не говорит про реальное состояние подключения.

### 2. Segments (namespaces)

Список объединяет сегменты всех выбранных кластеров. `. Маска вида `prod-*, stage-*` фильтрует длинный список.
Пустой выбор означает «все namespaces».

### 3. Service

Deployment, StatefulSet и DaemonSet по имени или маске; можно отметить несколько сервисов сразу, в разных
кластерах и сегментах. Поды находятся по label-селектору выбранного ворклоада.

### 4. Параметры логов

`--timestamps`, `--previous` (логи предыдущего запуска для перезапущенных контейнеров) и окно по времени
(`--since`). По умолчанию качается весь лог целиком; окно оставляет только последние N минут и это самый дешёвый
способ сократить объём.

Метки времени нужны формату «один общий файл»: без них строки разных подов нельзя разложить по хронологии.

### 5. Выгрузка

Три формата: zip (файл на под), папка (файл на под), один общий файл, где строки всех подов слиты по времени.

## Какой контейнер скачивается

Всегда ровно один контейнер на под - тот, который указан в аннотации пода. Ключи проверяются по порядку:

1. `kubectl.kubernetes.io/default-logs-container`
2. `default-logs-container`
3. `kubectl.kubernetes.io/default-container`
4. `default-container`

Sidecar-контейнеры (istio-proxy и подобные) не скачиваются. Под без этих аннотаций отдаёт свой первый контейнер.
Кнопка «Показать, что будет скачано» перечисляет по каждому поду, что берётся (`+`) и что отбрасывается (`-`).

## Что получается на выходе

Файл на под: `<кластер>/<namespace>/<сервис>/<под>.log`, плюс `manifest.json` с описанием прогона - параметры,
все поды, выбранный и отброшенные контейнеры с причинами, список файлов с размерами, ошибки и предупреждения.

Имя контейнера дописывается к имени файла, только если отличается от имени сервиса.

## Частичные права

Namespace, который пользователю не виден, попадает в сворачиваемое предупреждение под соответствующим шагом, а
всё читаемое по-прежнему находится и скачивается - `Forbidden` в одном сегменте не прерывает поиск. На шагах 2 и
3 есть счётчики по каждому кластеру: сколько сегментов загружено, сколько сервисов найдено. Кластер, который
ничего не вернул, подсвечивается, а не растворяется в общем списке.

## Параллельность

Каждый запрос — отдельный процесс `kubectl`, поэтому всё, что можно, выполняется одновременно:

* загрузка сегментов: до 6 кластеров одновременно;
* поиск сервисов: до 3 кластеров, и внутри каждого до 6 сегментов;
* проверка доступности кластеров: до 6 одновременно;
* скачивание логов: 4 контейнера одновременно.

Ошибка одного пода или сегмента не прерывает остальные: она попадает в список ошибок прогона. Отмена глушит все
живые процессы `kubectl`.

## Сборка из исходников

```sh
nvm install 16.14.2
npm ci
npm run build
npm pack
```

Получится `mmmatvey122-k8s-logs-menu-1.0.1.tgz` — этот файл и устанавливается в OpenLens.

## Структура кода

| Путь | Назначение |
| --- | --- |
| `renderer.tsx` | регистрация страницы, пунктов меню и команды |
| `main.ts` | обработчики IPC, каталог кластеров, резолв kubectl, диалоги сохранения |
| `src/common/types.ts` | типы и имена IPC-каналов |
| `src/common/containers.ts` | выбор контейнера по аннотации |
| `src/common/scope.ts` | согласованность выбора кластеров, сегментов и сервисов |
| `src/common/paths.ts` | имена файлов под ограничение длины пути |
| `src/common/pool.ts` | ограниченный параллелизм |
| `src/main/kubectl.ts` | поиск и запуск kubectl |
| `src/main/k8s.ts` | запросы namespaces, воркладов и подов |
| `src/main/probe.ts` | проверка доступности кластера |
| `src/main/collector.ts` | сбор логов, манифест, упаковка |
| `src/main/zip.ts` | потоковый ZIP без внешних зависимостей |
| `src/renderer/service-logs-page.tsx` | страница мастера |
| `src/renderer/ipc.ts` | IPC на стороне интерфейса |
